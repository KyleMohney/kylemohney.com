4️⃣ INLINE VS MODULAR CODE RULE
Code Type	Location	Notes
Page-specific content or visuals	Inline on that page	e.g., hero layout, inline CSS for that page
Reusable global components	Modular files	e.g., header.js, footer.js, style.css, chatbot.js
Shared animations or fonts	/styles/animations.css and /styles/theme.css	Must be imported globally
Shared data	/data/	e.g., chatbot JSON, service tier configs
5️⃣ NAMING CONVENTIONS

HTML files: all lowercase, hyphen-separated (about.html, join.html)

JS files: camelCase (headerInject.js)

CSS files: kebab-case (styles.css, theme-earth.css)

Classes: BEM naming (.hero__title, .service-card__description)

IDs: descriptive but minimal (#provider-form, #chatbot-container)

Variables: rootedPrimary, rootedAccent, etc.

7️⃣ BRAND TONE & COPY RULES

Every text element, heading, and tooltip must:

Use empathetic, empowering language.

Emphasize connection, trust, and natural alignment.

Avoid clinical jargon; balance human warmth with professionalism.

Maintain short, action-based CTAs: “Find Care”, “Join the Network”, “Book a Session”.

8️⃣ TECHNICAL STANDARDS

HTML5 semantic structure (header, section, article, footer).

Fully responsive (min width: 360px).

Accessible: aria-labels, color contrast ≥ 4.5:1, alt text on all images.

All buttons/toggles keyboard navigable.

No inline JS except page-specific scripts at the bottom of that file.

All assets lazy-loaded.

9️⃣ JS BEHAVIOR STANDARDS

Every script file begins with:

// Rooted Vitality Modular Script
// Purpose: [one-line summary]


and ends with:

// End of [file name] — Rooted Vitality Modular Script


Each script uses modular IIFE or ES module imports, with clear section numbers and labels.
